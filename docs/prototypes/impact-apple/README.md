# Impact：从观测到经验改进的交互原型

日期：2026-09-08，America/Los_Angeles。状态：原型已确认，正式产品已按此方向整体替换；见[迁移记录](../../tasks/2026-09-08-impact-production-migration/handoff.md)。

本轮按用户指定的 [Apple Design skill](https://github.com/emilkowalski/skills/tree/main/skills/apple-design) 重整整个 Impact。前一轮只实现了评测工作台和总览反馈入口，本轮覆盖概览、任务记录、改进工作台、验证，以及连接说明和异常状态。

## 打开与体验

在仓库根目录运行：

```sh
bun docs/prototypes/impact-apple/server.ts
```

打开 [本地原型](http://127.0.0.1:4760/)。服务只监听本机；全部图标、样式和脚本在此目录，不依赖 CDN 或真实项目 API。所有任务名、查询、数字、验证结果均为示例。反馈、草稿、验证历史与应用状态只保留在当前页面，刷新会重置。

建议体验：

1. 概览 → 查看并改进 → 阅读三条问题来源 → 修改经验 → 运行示例验证 → 应用 → 查看验证记录。
2. 总览中的待反馈入口 → 查看任务与经验 → 记录有帮助 / 不相关 / 有误导 → 撤销。
3. 加载状态漏召回 → 手工补充查询 → 验证 → 收录检索例子。这条路径不会修改经验正文。
4. 点击工具栏“示例数据”：切换深浅色、减少动态效果、演示读取失败、重置数据。项目选择器提供空状态。

## 信息架构与判断边界

| 区域 | 用户在这里决定什么 | 主要交互 |
|---|---|---|
| 概览 | 哪条经验值得先处理 | 按具体问题进入任务或改进；分别显示展示次数、反馈分母、已完成改进 |
| 任务记录 | 当时的经验是否有帮助 | 可辨认的任务列表、检索上下文、展示时版本、单步反馈、只读详情 |
| 改进工作台 | 应该修改经验，还是补检索例子 | 确认问题 → 编辑草稿 → 验证并应用；查看来源；应用后追踪；回滚 |
| 验证 | 改动改善了什么、损害了什么 | 同组用例比较、历史记录、变化与失败筛选、正反例数量、逐例证据 |

任务完成、检查通过、经验被展示、用户认为有帮助是四种不同事实。原型不会把它们合并为一个成效分数。无反馈不是负反馈，缺失数据不是零，离线检索通过不等于真实编码任务改善。新版本刚应用时显示“待观察”，不生成后续效果。

示例的最近 7 天数据由记录推导：8 条任务、7 次经验展示、6 次已反馈、其中 3 次有帮助。另有 1 条更早任务可在“全部记录”查看。已完成改进独立注明“全部时间”。问题工作单保留其创建时的来源，不随时间筛选静默消失。

## Apple Design 的具体实现

- 系统字体、字号对应的行高与字距；标题、正文和辅助信息靠字重、间距建立层级。
- 侧栏与工具栏使用材质区分导航层；主要内容保持实色和克制分组，蓝色用于操作和当前选择。
- 按下按钮即时反馈；桌面右侧面板与手机底部面板遵循同一进入、退出方向。
- 面板用 Pointer Events 与 pointer capture；从当前呈现位置开始拖动，以最近 80 ms 的速度样本决定释放趋势。动量投影采用 0.994 衰减，临界阻尼弹簧响应 0.34 s。拖动可以打断回弹并继续关闭。
- 原生 dialog 管理焦点和背景隔离，支持 Escape、关闭按钮、背景点击。手机查询对照表按例子重排，避免依赖横向滚动才能看到候选结果。
- 尊重系统减少动态效果、减少透明度与提高对比度设置；原型面板另有减少动态效果开关。重要手机控件提供至少 44 px 点击高度。
- 图标来自 Phosphor Icons 2.1.1 的正式 SVG，许可见 [icons/LICENSE](icons/LICENSE)。没有复制 SF Symbols 字体资源。

### 需要补齐的读模型

- **任务可读上下文**：可选 `display_title`、`summary`、`query_excerpt`，每项附采集来源和可用状态。标题首先允许用户命名；自动采集需要显式开启、长度限制、脱敏与删除策略。未启用时显示客户端、时间和简短标识，不伪造自然语言任务名。
- **改进工作单列表**：项目身份 + scope + trap_id + 展示时 revision 作为经验身份；关联 event_id/source_ref，列出问题类别、反馈分布、来源任务、草稿与验证状态。相同经验编号在 global/project 不可合并。
- **聚合查询**：将时间窗、任务筛选和待反馈计数下推服务端；列表使用 cursor/limit，检索事件惰性加载。总数应来自完整投影，不把分页第一页数量当全量指标。
- **验证记录**：冻结查询、期望经验的标题/版本、语料摘要、检索参数、实际排名和评分器版本。回看时不重新读取当前经验并替换历史证据。
- **应用后反馈**：只有与应用 receipt 的 after revision 精确匹配的展示才纳入；给出展示数、已反馈数、采集可用状态。无匹配证据显示未知或待观察，不计算虚假的改善率。

### 写操作与恢复

1. 轻量反馈独立于创建修订。请求携带项目、run、event、scope、trap、revision 与幂等键。撤销应追加有明确身份的更正事件，不能删除已有审计链；需要扩展正式反馈语义，原型中的内存回退不能直接复用。
2. 草稿按项目与来源隔离；异步请求开始时捕获归属，响应时校验。切换项目、返回、加载失败不能清空编辑内容；恢复草稿不恢复旧的验证或应用授权。
3. 验证必须绑定完整草稿摘要与冻结语料。内容、用例、基础版本变化均使结果失效。保存与应用检查 expected digest；冲突保持草稿并显示实际差异。
4. 应用沿用现有原子 commit receipt 与精确基础版本校验。回滚也检查当前版本，避免覆盖别人后续修改。已完成修订再次修改应生成新草稿，不能复活原 receipt。
5. 漏召回是新增/修改检索用例的入口。查询缺失时由用户补充；允许收录失败例子，并清楚显示尚未解决。该动作不等于经验内容变好。

建议分三步落地：先把现有数据接入四区导航、任务阅读与反馈；再接工作单聚合、独立修订及验证；最后增加可选任务上下文采集和版本后的长期反馈。真实 embedding / Agent 配对试验仍属于独立能力，不能用本原型的数据代替。
