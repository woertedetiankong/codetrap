# codetrap — Codebase Audit

_Analysis date: 2026-07-05. Covers the web console, storage layer, search/embeddings, session mode, and the CLI/MCP surface._

_Remediation status (2026-07-06): the Critical/High findings are resolved with two caveats — C1, C2, C4–C8 are **fixed** with regression tests; **C3** is resolved as documentation only (the approval gate is documented as advisory; `require_review` enforcement was deliberately not built); and **C9** is fixed only at tier (a) (the Bun shim), with tiers (b) postinstall warning and (c) the Node port still open. Also **fixed** with regression tests: U9, M1, M2, M3, M4, M5, M6, M7, M8, M13–M29, M31, and M32. The full suite (186 tests) and `tsc --noEmit` pass. Per-finding status notes below. Remaining open: C3 enforcement and C9 tiers (b)/(c); M9–M12 (M11 partially done), M30; the Low findings; and the architecture items. (2026-07-07: M3, M4, M7, M32 fixed.)_

codetrap is a well-architected project: a single runtime dependency, cleanly layered `queries → repository → store` data access, and one shared `TrapOperations`/`SessionOperations` core that the CLI, MCP server, and web console all sit on top of (no reimplementation across surfaces). The issues below are worth fixing precisely because the foundation is sound.

**Overarching theme (first principles):** the product is built for AI agents, but its two safety-critical invariants — "nothing enters `traps.db` without human approval" and "a trap ID identifies a trap" — are both unenforced. Most high-severity findings are downstream of that.

Severity legend: **Critical** = security or silent data loss · **High** = correctness defect that defeats the product's purpose · **Medium** = wrong behavior or meaningful UX failure · **Low** = polish / latent.

## Critical / High severity (fix first)

### C1 — Path traversal in the web server (arbitrary directory deletion) · Critical
- **Where:** `src/web/server.ts:275` → `src/lib/session-store.ts:598,408`
- **Evidence:** the request's `sessionId` is passed straight into `deleteSession()`, which builds the path as `join(sessionsDir, id)` with no validation, then `rmSync(dir, { recursive: true, force: true })`. A `sessionId` of `../../../other-project/.codetrap/sessions/<id>` deletes a **different** project's session tree and returns `{"success":true}`. Reproduced live during the audit. The same unsanitized path exists in `/api/session/cleanup` and the candidate routes. Token-gated and localhost-bound, but still critical local data loss.
- **Fix:** validate every `sessionId`/`id`/`scope` against `^[A-Za-z0-9._-]+$` before it reaches the filesystem layer.
- **Status: ✅ fixed.** `assertSafeSessionId` enforces `^[A-Za-z0-9._-]+$` (rejecting `.`/`..`) inside `SessionStore.sessionDir()` — the single chokepoint where ids become paths — so web, CLI, and MCP are all covered. Regression test: `session-maintenance.test.ts` ("rejects session ids that would escape the sessions directory").

### C2 — `session accept` is not atomic (retries + double-clicks duplicate traps) · High
- **Where:** `src/lib/session-operations.ts:211-238`; UI has no in-flight guard at `src/web/client-script.ts:1306-1376`
- **Evidence:** `addTrap` writes to SQLite **first**, then evidence, then supersede, then the candidate's `proposed→accepted` transition commits. If any later step throws (evidence failure, supersede miss, or a concurrent accept losing the status guard), the trap is already committed while the candidate stays `proposed`, so retrying inserts a second identical trap. Two concurrent accepts produced two traps, one an orphan with no candidate link. Detail-pane buttons aren't disabled in-flight, so a fast double-click reproduces it.
- **Fix:** wrap add+evidence+supersede+accept in one transaction, order the candidate status-guard first, and disable the action buttons on submit (re-enable in `finally`).
- **Status: ✅ fixed.** `SessionOperations.acceptCandidate` runs trap+evidence+supersede *and* the candidate's `proposed→accepted` file transition inside one SQLite transaction (new `TrapStore.transaction(scope, fn)`); the status guard throwing rolls back the DB writes, so a retry cannot duplicate. Web detail-pane buttons disable in-flight via `runDetailAction`. Bonus: M31 (Cancel on reject prompt) fixed in the same pass. Regression test: `session-maintenance.test.ts` ("re-accepting a candidate rolls back instead of inserting a duplicate trap").

### C3 — The human-approval gate is convention-only · High (design gap)
- **Where:** `src/commands/workflow.ts:82` (`add`), `src/mcp/tools.ts:44` (`add_trap`)
- **Evidence:** the product promise is "nothing is written to `traps.db` until a human accepts a candidate," but `codetrap add` and the MCP `add_trap` both write directly to the DB, and `session accept --accept-anyway` is callable by the same agent that captured the candidate. Nothing distinguishes a human from an agent; the gate exists only in template prose.
- **Fix:** add a `require_review` mode that redirects `add`/`add_trap` into the candidate inbox and ship mutating MCP tools opt-in — or document plainly that the gate is advisory.
- **Status: ✅ documented (enforcement not implemented).** README's Session Mode section now carries an explicit "Trust model" note stating the gate is advisory and that `add`/`add_trap`/`session accept` are callable by the capturing agent. A `require_review` enforcement mode changes the `add`/`add_trap` contract for every integration — deliberately left as a product decision.

### C4 — Trap IDs are per-database, but mutations treat them as global (silent wrong-DB writes) · High
- **Where:** `src/lib/trap-mutation-result.ts:22-27`, `src/lib/scope-context.ts:71-73`
- **Evidence:** unscoped mutations try project then global and take the first success; both DBs autoincrement from 1, so `codetrap delete 3` with no `--scope` deletes **global** trap #3 whenever project #3 doesn't exist — wrong content, exit 0, scope buried in output. Affects `delete`, `archive`, `supersede`, `update`, `add_trap_evidence`.
- **Fix:** when an unqualified ID resolves in more than one scope (or the preferred scope misses), refuse and require `--scope`; surface scope-qualified handles (`p:3`/`g:3`) in list output.
- **Status: ✅ fixed (refusal).** `TrapStore.resolveMutation` pre-checks the id in each reachable scope: exists-in-both and exists-only-in-non-preferred-scope both refuse with a structured `error` telling the caller which `--scope` to pass (surfaced in text and `--json` output for delete/archive/supersede/update/add_trap_evidence). The `p:3`/`g:3` list-output handles were **not** added — list output already groups by scope. Regression test: `cli-json.test.ts` ("unscoped mutations refuse ambiguous or wrong-scope trap ids").

### C5 — No timeout on embedding HTTP calls (default search can hang forever) · High
- **Where:** `src/lib/embedder.ts:57,131`
- **Evidence:** both `fetch()` calls pass no `signal`. Hybrid is the default mode and every search awaits `provider.embed([query])`, so a wedged Ollama socket blocks `codetrap search` indefinitely with no error and no fallback.
- **Fix:** `signal: AbortSignal.timeout(ms)` on both calls (≈10s query / 60s batch), mapping abort to the provider-unavailable path so hybrid falls back to FTS.
- **Status: ✅ fixed.** `AbortSignal.timeout` on the Jina embed, Ollama embed (10s single-text / 60s batch), and Ollama health probe (3s) fetches, with timeout errors mapped to readable messages. Hybrid already catches semantic-path errors and falls back to FTS with a diagnostic, so a wedged provider now degrades instead of hanging. Tests in `ollama-embedder.test.ts`.

### C6 — v5→v6 embedding migration is non-transactional and non-reentrant (silent total loss of embeddings) · High
- **Where:** `src/db/schema.ts:198-234` (and implicit migration on every open at `src/db/connection.ts:35`)
- **Evidence:** `ALTER TABLE ... RENAME TO trap_embeddings_legacy_v5` is autocommitted; if the process dies before the data copy, the next open sees no `trap_embeddings`, recreates it empty, stamps `version=6`, and orphans the legacy table forever — no error. Migrations run implicitly on every open (even `list`) with no backup.
- **Fix:** wrap each migration step in a transaction, make the v6 guard detect and resume from the leftover legacy table, and snapshot the DB (via the existing `backupScopeDatabase` helper) before applying migrations.
- **Status: ✅ fixed.** All migrations now run in a single `BEGIN IMMEDIATE` transaction with the version re-read under the lock (also fixes M1's race); the v6 step detects a leftover `trap_embeddings_legacy_v5` and resumes the copy — including on DBs a pre-fix binary already stamped v6 with an empty table; and file-backed DBs with existing data are snapshotted to `backups/traps.db.pre-migration-vN.<timestamp>.backup` before migrating (M5). Also added M2's forward-version guard. Tests in `embedding-profile-storage.test.ts` (recovery, forward-guard, backup).

### C7 — Export→import silently drops lifecycle fields · High
- **Where:** `src/lib/trap-codec.ts:63-80`, `src/lib/store.ts:286-291`
- **Evidence:** `importRecordToTrapInput` maps only `TrapInput`, discarding `status`, `state_key`, `supersedes_id`, `valid_from/until`, `hit_count`, `created_at`, `updated_at` that `exportTraps` faithfully wrote — so an archived or superseded trap re-imports as a fresh `active` trap with a severed supersede chain. Export/import is unsafe as backup/restore.
- **Fix:** use the record-preserving insert path from `trap-transfer.ts:52-78` (which already remaps `supersedes_id`) in `importAll`.
- **Status: ✅ fixed.** `importAll` now inserts via a record-preserving path (`importRecordToTrapRecordInsert` → `insertTrapRecord`) that keeps `status`, `state_key`, `valid_from/until`, `hit_count`, and timestamps, and remaps `supersedes_id` within the batch per scope. Legacy minimal import JSON still works (fields default sensibly). Regression test: `import-export-cli.test.ts` ("export→import preserves lifecycle fields and the supersede chain").

### C8 — Path-glob matching silently drops traps · High
- **Where:** `src/lib/trap-scope-match.ts:96-98` and `:54-71`
- **Evidence:** `**/*.ts` compiles to a regex requiring a literal `/`, so it never matches top-level files like `index.ts`; and global-scope traps (no `project_path`) can never match against an absolute `--path` because only an absolute candidate is derived. Since a non-match **excludes** the trap, an agent hook passing a file path silently loses applicable lessons.
- **Fix:** compile `**/` as `(?:[^/]*/)*` (consume the trailing slash) and bare `**` as `.*`; for relative globs, also test suffix segments of an absolute candidate path.
- **Status: ✅ fixed.** `globToRegExp` compiles `**/` as `(?:[^/]*/)*` so `**/*.ts` matches `index.ts`; `globMatchesPath` additionally tries every suffix of an absolute path's segments when the glob is relative, so global-scope traps apply again. Tests in `trap-applicability.test.ts` (three new cases including an end-to-end global-trap search with `--path`).

### C9 — Bun-only npm package fails silently on Node-only machines · High
- **Where:** `bin/codetrap:1`, `package.json:23-25`, `src/db/connection.ts:1`
- **Evidence:** `#!/usr/bin/env bun` with `bun:sqlite` and Bun text-imports; npm doesn't enforce the `engines.bun` constraint. `npm install -g codetrap` on a Node box succeeds, then every invocation dies with `env: 'bun': No such file or directory` — the worst first run for the primary audience. Compiled binaries exist in GitHub Releases, but the doc pointing to them was deleted (see U9).
- **Fix (tiered):** (a) a `sh`/node shim that detects missing Bun and prints the binary-download URL; (b) a `postinstall` warning; (c) longer term, port `bun:sqlite`→`node:sqlite` (Node ≥22) and text-imports→`readFileSync` — the only hard Bun couplings.
- **Status: ✅ fixed (tier a).** `bin/codetrap` is now a POSIX-sh shim that resolves symlink chains, execs Bun with the package's `src/index.ts` when present, and otherwise exits 1 with Bun-install instructions and the GitHub Releases binary URL. Verified live on a Bun-less PATH and through a symlinked install. Tiers (b) postinstall warning and (c) Node port remain open.

## Medium severity

### Storage
- **M1 — No concurrency guard around schema detection/migration.** `src/db/schema.ts:13-26` does a non-serialized check-then-act; concurrent CLI+MCP+web opens can both run migrations and duplicate the `schema_version` row. Fix: wrap version-check + migrations + version-write in one `BEGIN IMMEDIATE`; constrain the table to one row. **Status: ✅ fixed with C6** — one `BEGIN IMMEDIATE` transaction, version re-read under the lock, and `setSchemaVersion` rewrites the table to a single row.
- **M2 — No forward-version guard.** `src/db/schema.ts:16` only handles `current < SCHEMA_VERSION`; older code opening a newer DB proceeds and later fails with raw SQLite errors. Fix: throw a clear "DB schema is newer than this codetrap; upgrade" error. **Status: ✅ fixed with C6** — `initSchema` throws "newer than this codetrap build … Upgrade codetrap."
- **M3 — Cross-DB project migration is not atomic.** `src/lib/scope-migration.ts:226-253` commits the destination copy before deleting from source; a crash in between leaves traps duplicated in both DBs. Fix: `ATTACH DATABASE` so copy+delete run in one transaction, or a resumable journal. **Status: ✅ fixed.** The destination copy and the source delete now run in a single transaction on a single connection (the source is `ATTACH`ed to the destination), so any thrown error rolls back both — the old two-connection/two-commit sequence is gone. FK cascades and the FTS delete trigger fire against the attached source, keeping its index/evidence consistent. The residual hard-crash-mid-`COMMIT` window (which WAL cannot make atomic across two files) is covered by the pre-migration backups taken before the transaction. Regression tests: `scope-migration-cli.test.ts` (source FTS/evidence consistency after the attached delete; a forced mid-transaction failure rolls back both DBs with no duplication or loss).
- **M4 — Read-only maintenance connections skip `busy_timeout`.** `src/lib/scope-maintenance.ts:51,64` open with `{ readonly: true }` and bypass `configureDatabase`, so a concurrent writer makes export/backup fail instantly with `SQLITE_BUSY`. Fix: apply `PRAGMA busy_timeout` on these connections too. **Status: ✅ fixed.** Both read-only opens now route through `openReadOnlyDatabase()`, which sets `PRAGMA busy_timeout=5000` (matching `configureDatabase`) before use. Regression test: `scope-maintenance.test.ts` (asserts the pragma is applied; backup still succeeds).
- **M5 — Implicit migrations with no backup / no prompt.** Even `codetrap list` triggers full-table-rewrite migrations; backups exist only in the scope-migration path. Combined with C6 this is data-loss risk with no safety net. Fix: snapshot before `applyMigrations` on an existing file-backed DB. **Status: ✅ fixed with C6** — file-backed DBs with existing data are snapshotted to `backups/` before any migration runs.
- **M6 — Import silently drops failing records.** `src/lib/trap-archive.ts:34-38` swallows every per-record failure and `cmdImport` prints only `Imported N traps.` Fix: collect `{index, title, error}`, report `Imported N of M (K skipped: …)`, non-zero exit when K>0. **Status: ✅ fixed** — `importTrapArchive` returns `{ imported, total, skipped: [{index, title, error}] }`; the CLI prints `Imported N of M traps.` plus per-record skip reasons and exits 1 when anything was skipped (JSON mode gets the same fields with `success: false`).
- **M7 — Raw SQLite errors surface to users.** `updateTrap` never validates `category`/`severity`, so `edit … --json '{"category":"typo"}'` surfaces `CHECK constraint failed`. Fix: validate enum fields against `CATEGORIES`/`SEVERITIES`; map `SQLiteError` to friendly text at the top level. **Status: ✅ fixed.** `buildTrapInput`/`pickTrapUpdate` (add and edit paths) validate `category`/`severity` via `assertTrapEnum` and throw `Invalid trap <field>: <value>. Expected one of: …` before the DB; the top-level `errorMessage` maps any residual `SQLITE_CONSTRAINT*` error to friendly text as a safety net. Regression test: `cli-json.test.ts` (bad category/severity on `add` and `edit`, text + JSON envelope, no leaked `CHECK constraint`).

### Search / embeddings
- **M8 — Hybrid fallback diagnostic lost when FTS returns zero rows.** `src/lib/search-service.ts:80-91` staples diagnostics onto result rows, so `[]` carries no signal about whether semantic ran. Fix: return `{ results, diagnostics }` out-of-band. **Status: ✅ fixed (breaking CLI/MCP change)** — `SearchService.search` returns a `SearchOutcome { results, diagnostics }`; the CLI `search --json` and MCP `search_traps` now emit `{ results, diagnostics }` (per-row stapling kept for card display), text mode appends `note [code] (scope): …` lines, and the agent guidance tells readers to check `diagnostics` before treating empty `results` as "no pitfalls recorded". `repository.search()` keeps the plain-array shape for eval tooling.
- **M9 — Single-CJK-character queries can never match multi-char content.** `src/lib/search-normalizer.ts:43-46` emits a unigram for the query while the index stores only bigrams. Fix: index unigrams alongside bigrams, or emit a `缓*` prefix term for single-char CJK query tokens.
- **M10 — Length normalization crushes long traps (hybrid only).** `src/lib/search-policy.ts:171-173` applies `sqrt(anchor/length)` to RRF scores; one length penalty can outrank ~60 positions, and FTS/semantic apply none. Fix: drop it (bm25 already length-normalizes, cosine is length-invariant) or clamp to a small bounded multiplier.
- **M11 — Embedders don't fully validate returned dimensions.** Original: the Jina path checked only `Array.isArray`, so a dimension change makes `cosineSimilarity` return 0 and semantic search silently returns nothing. Fix: send `dimensions` in the request, validate response length, make `cosineSimilarity` throw/log on mismatch instead of returning 0. **Status: 🟡 partially fixed.** The Ollama path now sends `dimensions` (`src/lib/embedder.ts:164`) and validates each vector's length against `this.dimensions` (`:193`). The Jina path validates row *count* (`:101`) and array-ness (`:109`) but still does **not** send `dimensions` in the request nor check each vector's length against its declared `dimensions` (1024), so a Jina dimension change still slips through. And `cosineSimilarity` (`:269`) still silently returns `0` on a length mismatch instead of throwing/logging. Remaining: Jina per-vector length check + `dimensions` in the request; `cosineSimilarity` mismatch handling.
- **M12 — Ollama embedder ignores the `task` parameter.** `src/lib/embedder.ts:128` discards `_task`; qwen3-embedding needs a retrieval instruction prefix on queries, so queries and passages embed identically, reducing quality. Fix: prepend the retrieval instruction for `retrieval.query`.
- **M13 — Partially-indexed hybrid ranking is biased against the newest traps.** Embeddings are generated only on explicit `embed` and deleted on `update` (`src/db/repository.ts:49-51,87-92`); in `fuse` (`search-policy.ts:219-232`) embedded traps get two RRF contributions and unembedded ones get one, so recently added/edited traps rank below older embedded ones — with no per-search hint. Fix: embed synchronously on add/update when a provider is available; attach a `partial_index` diagnostic when `missing+stale>0`. **Status: ✅ fixed** — new `ensureEmbeddingForTrap` embeds the touched trap right after CLI `add`/`edit`, MCP `add_trap`/`update_trap`, and `session accept` (best-effort, outside the accept transaction, capped by the C5 timeouts; no provider → quiet no-op), and hybrid/semantic searches attach a `partial_index` diagnostic whenever `missing+stale > 0`.
- **M14 — Edited traps vanish from `--mode semantic` until manual re-embed.** `src/db/embedding-queries.ts:168-172` silently drops stale rows. Correct but invisible. Fix: count dropped rows and surface a diagnostic / doctor pointer. **Status: ✅ fixed with M13** — semantic mode returns the same `partial_index` diagnostic (counts + `codetrap embeddings reindex` pointer), and the embed-on-write hook re-embeds edited traps immediately so the window mostly disappears.

### Sessions
- **M15 — Lost-update races on session JSON files (no locking).** `src/lib/session-store.ts:509-556` does whole-file read-modify-write on `candidate-traps.json`/`index.json`; two concurrent captures compute the same `cand-001` and the last write silently deletes the other's candidate. Fix: move candidates/index/active-pointer into SQLite (see A2), or a per-project lockfile. **Status: ✅ fixed** — every `SessionStore` mutation now runs under a per-project lock (`.codetrap/sessions/.lock` via atomic `mkdirSync`, 5s wait, 10s stale-steal). Regression test spawns two concurrent CLI captures and asserts both candidates survive.
- **M16 — `session start` check-then-act race + active-pointer resurrection.** `src/lib/session-store.ts:108-142,459-463`: two concurrent starts both pass the "no active session" check; the loser stays `active` in the index and later gets resurrected by the index-scan fallback. Fix: use `mkdirSync(dir, { recursive: false })` as the uniqueness lock; write `active.json` via temp+rename. **Status: ✅ fixed** — `startSession` re-checks the active session under the M15 lock, creates the session dir with `recursive: false` as belt-and-braces, and `active.json` is written via temp+rename.
- **M17 — Non-atomic writes + unguarded `JSON.parse` brick all session commands.** `src/lib/session-store.ts:491,514,540,568`: plain `writeFileSync` (no temp+rename) plus bare `JSON.parse(...) as T`; a crash mid-write leaves truncated JSON, after which every session command — including `session delete` — dies with a raw `SyntaxError`. Fix: temp+rename on all writes; wrap parses with the file path; let `delete` proceed without parsing. **Status: ✅ fixed** — all session JSON writes go through `writeFileAtomic` (temp+rename), parses go through `readJsonFile` ("Corrupt session file <path>: …"), and `session delete` works with all three JSON files corrupt, rebuilding the index from surviving session dirs as a side effect. Tests in `session-maintenance.test.ts`.
- **M18 — Conflict check never looks at the other scope.** `src/lib/session-conflicts.ts:26` searches only the candidate's own scope, so a project candidate duplicating a global trap is accepted with `conflict_status: "none"`. Fix: search with `scope: undefined` (both DBs). **Status: ✅ fixed** — the conflict search now spans both scopes; a project candidate duplicating a global trap is blocked with the global trap listed in `possible_conflicts`. Regression test in `session-maintenance.test.ts`.
- **M19 — "same module" conflict rule guarantees false positives.** `src/lib/session-conflicts.ts:59-60`: any existing active trap in the module counts as a conflict regardless of topic, training agents to reflexively pass `--accept-anyway`. Fix: require module match AND (title-token overlap or tag intersection), or downgrade bare same-module to a non-blocking warning. **Status: ✅ fixed** — a module match now also requires tag intersection or ≥2 shared title tokens (reason string: "same module and overlapping topic"); a same-module candidate on an unrelated topic accepts cleanly without `--accept-anyway`. Regression test in `session-maintenance.test.ts`.
- **M20 — Session-note markdown round-trip is lossy and injectable.** `src/lib/session-codec.ts:64-92,203-210`: `note.text` written verbatim, parser splits on `^###` with no fence awareness and hoists any `Source ref:`/`Related files:` body line into metadata. Fix: escape/indent body lines matching header/metadata patterns; track fences; longer term store notes as JSONL. **Status: ✅ fixed.** `formatSessionNote` now backslash-escapes any body line that would be misread as a note header (`### <ts> <kind>`), `Source ref:`, or `Related files:` (including already-backslashed lines over a structural core, for lossless nesting); `parseNoteBlock` reverses it and never hoists an escaped line into metadata. Escaping is line-based so fenced code is protected without separate fence tracking, and ordinary bodies are byte-identical on disk. Regression test: `session-codec.test.ts` (header/metadata injection, fenced code, literal-backslash, and "a crafted body cannot inject a second note").
- **M21 — `session capture` with invalid `--kind` leaks a permanently active auto-session.** `src/lib/session-operations.ts:140-154`: the auto-session is created before `parseSessionNoteKind` throws, and is never closed. Fix: validate `kind` before `startSession`; wrap the created-session path in try/catch that closes it on failure. **Status: ✅ fixed.** `captureCandidate` calls `parseSessionNoteKind(request.kind)` before any session is created (so an invalid kind never starts one), and the capture body runs inside a try/catch that deletes the auto-session if a later step throws — but only when this call created it, so an existing active session is never destroyed. Regression test: `session-maintenance.test.ts` ("capture with an invalid kind leaves no active auto-session").

### CLI / MCP
- **M22 — Flag parser swallows positionals; `--flag=value` ignored.** `src/commands/workflow.ts:134-147`: `codetrap search --json timeout` consumes `timeout` as the value of `--json` and loses the query; `--limit=5` is silently ignored (no `=` split). Fix: explicit boolean-flag allowlist and `=` splitting, or adopt `util.parseArgs`. **Status: ✅ fixed** — `parseArgs` now has a boolean-flag allowlist (json, output-json, no-rerank, force, apply, dry-run, …) and splits `--flag=value`; `search --json parser` keeps the query and `--limit=1` is honored. Tests in `cli-json.test.ts`.
- **M23 — Six commands crash with raw stack traces on common bad input.** `cmdShow/Delete/ArchiveTrap/SupersedeTrap/Export/Stats/Doctor` have no try/catch and `src/index.ts` has no top-level `.catch`; `--scope bogus` throws an unhandled stack. A corrupt `~/.codetrap/config.json` bricks every command including `doctor` (`src/lib/config.ts:48-54`). Fix: wrap dispatch in one `errorFrom` handler; degrade to defaults on bad config with a warning. **Status: ✅ fixed** — `executeCommand` wraps the whole dispatch in one `errorFrom` handler (plus a top-level catch in `index.ts`), so `--scope bogus` prints `Error: Invalid scope: bogus` with no stack; a corrupt config warns once ("ignoring invalid codetrap config at <path>") and degrades to defaults, keeping `stats`/`doctor` working.
- **M24 — `--json` means three different things.** Input on `add`, output on `search`/`list`, split on `add_trap_evidence`. An agent that learned "output" corrupts an `add`. Fix: `--json` always means output; rename input flags to `--input-json`. **Status: ✅ fixed (breaking CLI change)** — `--json` is now always a boolean output flag; JSON input moved to `--input-json` on `add`/`edit`/`add_trap_evidence`; `--output-json` kept as an output alias. Legacy `add --json '{…}'` invocations fail loudly with a migration hint instead of misbehaving. README, installation doc, and skill templates updated.
- **M25 — Errors are not JSON even when `--json` was requested.** `src/commands/workflow.ts:223,245` emit plain-text not-found on stderr while `delete` emits structured error — inconsistent contract for agents. Fix: route all failures through a uniform `{ success:false, error }` envelope when `--json` is present. **Status: ✅ fixed** — all thrown errors and not-found/edit failures return `{ "success": false, "error": … }` on stdout with exit 1 whenever `--json`/`--output-json` is present (usage-string errors for missing positional args remain plain text on stderr).
- **M26 — MCP `search_traps` ignores user config defaults.** `src/mcp/server.ts:38` hardcodes mode/rerank while the CLI honors `searchDefaultsFromConfig()`. Fix: call `searchDefaultsFromConfig()` in the handler. **Status: ✅ fixed.** The `search_traps` handler now builds its request with `searchDefaultsFromConfig()` (config + `CODETRAP_SEARCH_*` env), so MCP and CLI honor the same defaults; per-call args still override. ## Architecture assessment (first principles)

- **A1 — Project identity should not be an absolute path string.** Traps are keyed to `project_path` matched by exact string (`src/db/queries.ts:271`) with no `realpath`, so a symlinked cwd or a directory rename silently orphans every trap until the user finds `migrate-project`. This is the root cause behind both C4 and the migration tooling's existence. Fix: mint a stable UUID in `.codetrap/project.json` at `init`, key traps to it, treat the path as display metadata.
- **A2 — Session state is four hand-synchronized JSON files with no locking** (`session.json`, `index.json`, `active.json`, `candidate-traps.json`), all whole-file read-modify-write. This is the shared root cause of M15/M16/M17. This relational, concurrent data belongs in the SQLite DB that already has WAL + `busy_timeout`; keep only append-only notes as files.
- **A3 — Retrieval pipeline is mostly sound** (retrieve → filter → fuse → rerank, with rerank correctly before the final truncation), but the applicability filter runs after SQL `LIMIT` (`src/lib/search-policy.ts:128` vs `queries.ts:74-85`), so a selective `--path` can miss matches beyond the top candidates; and see M13 for the newest-trap ranking bias.
- **A4 — `router.ts` is vestigial** (9 lines; the real 825-line adapter is `workflow.ts`, which mixes parsing, dispatch, and presentation). The `CommandResult` contract and shared-operations core are the good parts; the CLI adapter has grown unwieldy and could be split by domain.
- **A5 — Web client shipped as TS-template strings** with functions serialized via `toString()` (`src/web/client-review.ts:169`). Currently works even through `bun build --compile`, but it silently depends on Bun preserving function source. Fix: add a smoke test asserting the inline script parses (`new Function(script)`) so a regression fails CI instead of the whole UI.

### Worth preserving (positives)
- Single runtime dependency (`@modelcontextprotocol/sdk`), lazily imported only on `serve`.
- Profile-keyed embedding cache with passage-hash invalidation is a clean cache-invalidation design.
- XSS escaping in the web client is applied consistently — no injection found; all DB/user text routes through `escapeHtml`/`escapeAttr`.
- `configureDatabase` correctly orders `busy_timeout` before WAL and `foreign_keys=ON`.
- No SQL injection found — all user data is bound via `?`; the FTS literal compiler safely quotes/doubles terms.
- The shared `TrapOperations`/`SessionOperations` core means CLI, MCP, and web don't reimplement trap/session logic.
